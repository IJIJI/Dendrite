# Ports and Program Instances — core plan

Design settled 2026-09-06; implementation timing is decided separately (see the last section).
The plan for taking inputs and outputs out of `Language`, making them layered data (`Ports`),
and giving core the per-program object that owns a program together with its layers
(`ProgramInstance`). It supersedes the "surface ownership" row of `editor-plan.md` and the
`provided` / `userInputs` config sketched there; Phase 3 of the editor plan builds on this.

---

## Why

- `Language` bundles vocabulary (types, ops, evaluators, grammar) with a program's inputs and
  outputs. A language is a build artifact shared by tests, the playground, the docs and Beacon;
  inputs and outputs vary per deployment and per program. Today the editor works around this by
  copying the language per document and mutating the copy (`extendLanguage` + `applySurface`).
- Beacon needs three kinds of declarations at once: a fixed host contract (`$busses`, `$watched`,
  output `tally`), per-lighthouse capability additions (output `strobe`, input `$ambientLight`),
  and user additions that are editable in a UI and shown outside the editor. Some of that must
  change while a runtime is live (a device reconnects, a user adds an input).
- The editor's word for these declarations, "surface", now collides with the brand's *surfaces*
  (backgrounds). The concept needs its own name before it becomes core API.

---

## Decisions (settled — do not reopen without a new driver)

| Decision | Choice | Why |
|---|---|---|
| **Vocabulary vs ports** | `Language` = types, ops, evaluators, grammar. `registerInput` / `registerOutput` are removed. | One language version across every host; a runtime can be built with a different contract in a test without cloning the vocabulary. `createStdlib` has no inputs, so it is unaffected. |
| **Name** | `Ports` (`{ types?, inputs, outputs }`, pure data) · `PortLayer` (`{ id, ports, policy }`) · `ProgramInstance` | "Port" is graph vocabulary (one input or output = one port; the Rete view will draw them) and sits next to the brand's fixed words *input / output*. Rejected: *surface* (brand clash), *interface* (TypeScript), *contract* (one-sided), *connectivity* (Beacon-flavoured, long). |
| **Levels, not flags** | Shared layers hang on the `Runtime`; local layers hang on the `ProgramInstance`. Scope is where a layer is attached. | No `scope` field to keep consistent across instances, and one place per shared contract. |
| **Composition** | Ordered (host → capability → document); **no shadowing**: a name declared twice, or a document type shadowing a language type, is a compose error. Order decides display order and which layer a conflict is reported against. | Silent overrides of declarations would change types under a host. An explicit `overrides` field can be added when a consumer needs one. |
| **Policy, not kinds** | A layer carries `policy: { editable, feeds: "host" \| "user", persisted }`. Kinds (host, capability, document) are presets of that policy, applied by the host; core reads the fields only. | Strategy as data, open for extension: a new policy field is a default on a struct, not a new layer type or a branch in core. |
| **Values follow the level** | Shared values live in the runtime (`updateInputs`, shared names only); local values live in the instance (`setInput`, local names only). Triggers split the same way. | Two instances may both declare `$threshold` and never meet; within one instance compose forbids a local name equal to a shared one, so there is no lookup order. |
| **The instance** | `ProgramInstance` owns a saved program plus its layers; compiles through the environment; registers in the runtime; on a layer change recompiles and replaces itself (handlers and values kept); publishes `diagnostics`, `ports`, `outputs`, `values`; offers `snapshot()` and `onChange`. | The compiled `CoreProgram` is an immutable artifact; the runtime stays values plus evaluation; the missing object between them is this one. It is what the editor's `EditorSession` already is for one program, so the editor becomes an adapter. |
| **Storage** | `SavedProgram.ports?` carries the **document layer only** (optional field, no version bump). Host and capability layers are regenerated by the host and identified (capability ids, version) in the host's envelope. Values are runtime state: in the instance snapshot, persisted by whoever owns the document. | The authoring artifact stays canonical and portable; a program loaded on a poorer lighthouse fails with plain analyser diagnostics. |
| **Persistence** | Host policy, as now: `instance.onChange` hands out snapshots; store adapters stay in the editor package. | The instance can be "wired to a database" without core knowing about databases. |

## The model

| Level | Object | Holds | Values |
|---|---|---|---|
| Build | `Language` | vocabulary only | none |
| Deployment | `Runtime` | shared `PortLayer`s — the host contract every program sees | shared value map, `runtime.updateInputs` |
| Program | `ProgramInstance` | its own `PortLayer`s — capability and document | local value map, `instance.setInput` |

The descriptor a program is analysed against is `compose(language, runtime.layers,
instance.layers)`; every input in the result is tagged with the level it came from, and that tag
is all the runtime needs to route a value. The analyser and the evaluator do not change: they
still receive one descriptor.

### Layer policy presets

| Policy field | host | capability | document |
|---|---|---|---|
| `editable` — may an editor change the declarations | no | no | yes |
| `feeds` — who supplies values at runtime | host | host | user (UI fields, in the editor or in the host's own UI) |
| `persisted` — stored with the program | no, identity only | no, identity only | yes |

Programmatic and user mutations are the same call, `setLayer(id, ports)`; the editor simply
refuses it on a layer whose `editable` is false.

## API sketch

```ts
// core
interface Ports { types?: PortType[]; inputs: InputDefinition[]; outputs: OutputDefinition[] }
interface PortLayer { id: string; ports: Ports; policy: LayerPolicy }
interface LayerPolicy { editable: boolean; feeds: "host" | "user"; persisted: boolean }

composeLayers(language, shared: PortLayer[], local: PortLayer[]): ComposeResult
  // → { descriptor, provenance: Map<name, { layerId, level }> } | { problems: PortProblem[] }
  // problems: invalid_name · duplicate_name · shadowed_name · unknown_type

const runtime = env.createRuntime({ layers: [hostLayer] });          // shared
runtime.setLayer(id, ports);                                          // every instance recompiles
runtime.updateInputs(changes);                                        // shared names only

const instance = env.createInstance(runtime, saved, [capabilityLayer, documentLayer]);
instance.diagnostics · instance.ports · instance.outputs · instance.values   // observables
instance.setLayer(id, ports) · instance.setInput(name, value) · instance.setSource(text)
instance.snapshot()  →  { program: SavedProgram /* with document-layer ports */, values }
instance.onChange(listener)                                           // debounced snapshots
instance.dispose()

// runtime primitives the instance uses (public, so hosts without instances can too)
runtime.register(id, program, localPorts) · runtime.replace(id, program, localPorts)
handle.setInput(name, value)                                          // local, this program only
```

`SavedProgram` gains `ports?: Ports`. `LanguageDescriptor` keeps its shape for the analyser and
evaluator; its `inputs` and `outputs` are simply empty on a bare language and filled by
`composeLayers`.

## What changes, where

| Package | Change |
|---|---|
| core `infra/ports.ts` (new) | `Ports`, `PortLayer`, `LayerPolicy`, presets, `composeLayers` with validation (moves in from the editor's `surface-edit.ts`) |

| core `runtime/runtime.ts` | per-program local ports and values; `replace(id, program, ports)` keeps handlers and values; `setLayer` on shared layers; shared/local routing |
| core `runtime/instance.ts` (new) | `ProgramInstance` |
| core `infra/serialise.ts` | `SavedProgram.ports?` |
| core tests | every test that used `registerInput` passes a layer instead |
| editor `session.ts` | `EditorSession` becomes an adapter over `ProgramInstance` (its observables map one to one); `setLanguage` folds in |
| editor `document.ts`, `surface.ts`, `surface-edit.ts` | `EditorDocument` = instance snapshot + envelope version; `SurfaceSpec` → `Ports`; edit ops stay, validation is core's |

| docs | `architecture.md` (levels, host integration), `editor-plan.md` Phase 3, `beacon-reference.md` |

## Patterns and smells

| Pattern / smell | Where |
|---|---|
| **Composite** | layers compose into one descriptor; a layer is data, a stack is data |
| **Strategy as data** | policy presets instead of layer classes |
| **Memento** | `instance.snapshot()`; the document is the snapshot plus an envelope |
| **Observer** | the instance publishes; stores, panes and the host subscribe |
| **Facade** | `ProgramInstance` over environment + runtime for one program |
| Primitive Obsession — avoided | a `LayerPolicy` struct, never loose booleans in signatures |
| Speculative Generality — avoided | no override mechanism, no scope flag, no layer add/remove dynamics beyond `setLayer` until a consumer needs them |
| Divergent Change — avoided | one `PortLayer` type for host, capability and document |
| God Object — avoided | the runtime stays values plus evaluation; it does not parse or recompile |

## When

Three options; the trade is where the rewrite lands.

| | Now, before Phase 3 UI | After Phase 3 UI, before 0.1.0 | After 0.1.0 |
|---|---|---|---|
| Phase 3 editing UI is built on | layers (final shape) | `provided` / `userInputs` (throwaway), then rewritten | the copy model, published |
| Core publish | 0.1.0 ships the final model | same, later | 0.2.0 is a breaking change for Beacon |
| Cost | ~3 days now, 15a's `setLanguage` folds in | ~3 days plus the UI rewrite | ~3 days plus a migration |

Recommendation: now. Core is unpublished, the editor's surface editing has one commit in the
tree, and Beacon is the named consumer of every piece above.
