You have written programs now. This page says what happens to one, in enough detail to predict
what the language will do and no more.

<Chain />

Five steps. Each takes what is on its left and produces what is on its right, and none of them
can reach backwards.

## Lex: text becomes tokens

The lexer cuts your text into names, numbers, strings and symbols. A string with no closing
quote, or a character the language has no use for, is reported here, with a position.
[More on lexing](../../how-it-works/the-chain/#lex-characters-become-tokens).

## Parse: tokens become a program

The parser turns the tokens into bindings and outputs, and rewrites every symbol into the op it
stands for as it reads: `$price * $quantity{:den}` leaves as `Multiply($price, $quantity){:den}`.
It knows the shape of the language and nothing else, so a syntax error is reported here and a
misspelled op name gets through. [More on parsing](../../how-it-works/the-chain/#parse-tokens-become-a-raw-program).

## Compose: what the program may use

Checking a program needs a list of everything it may use: the language's ops and types, and the
inputs and outputs your application declared, which arrive in layers. Composing joins the layers
into one list. It reads what was declared, never what you wrote, so two layers claiming the same
name are reported here, before your code is looked at.
[More on composing](../../how-it-works/the-chain/#compose-the-descriptor-is-assembled).

## Analyse: the program is checked

The analyser works out the type of every binding and checks every op call. Two things to rely
on. **Errors are collected, not thrown at the first one**, so you get the full list at once.
And **soundness is per output**: a broken output is dropped and the others still run, unless
your application marked it *required*.
[More on analysis](../../how-it-works/the-chain/#analyse-the-raw-program-becomes-a-core-program).

## Evaluate: values, on demand

Outputs pull: asking for one walks only the nodes it depends on, so when an input changes, only
the nodes that read it recompute (you saw this on [Inputs](../writing/inputs/)). Two things to
rely on. **A binding is computed at most once per evaluation**, however many names read it. And
**the last good program keeps running**: while your text does not compile, the values on screen
are the ones from the program that did, marked stale rather than hidden.
[More on evaluation](../../how-it-works/the-chain/#evaluate-the-core-program-becomes-values).
